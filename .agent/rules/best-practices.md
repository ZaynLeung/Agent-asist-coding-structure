# 最佳实践与注意事项

## 工程实践

- 先定义验收标准：输入、输出、边界条件、失败模式与可验证步骤
- 先写最小闭环：用最小改动完成可运行、可验证的版本，再迭代增强
- 保持可追溯：重要决策写入 `.codex/memory/decisions.md`，并在变更处引用
- 以可维护性为优先：清晰的命名、最小耦合、合理抽象、避免重复
- 不引入未经确认的依赖：新增依赖必须说明目的与替代方案

## Prompt 调优原则

- 使用结构化输入：背景、目标、约束、样例、验收标准
- 避免过度指令：优先说明意图与约束，而非微操每一步
- 明确优先级：正确性 > 安全性 > 可维护性 > 性能 > 风格一致性
- 结果可复用：沉淀高频提示词到 `.codex/prompts/`

## 安全与合规

- 禁止输出/记录密钥、Token、Cookie、私钥等敏感信息
- 对外部输入做校验与最小权限访问
- 处理文件/网络操作前先确认影响范围与回滚方式

## 交付质量

- 提供验证方式：命令、测试用例或最小复现步骤
- 避免“半成品”：每次提交应保证仓库处于可读、可运行或可解释状态
