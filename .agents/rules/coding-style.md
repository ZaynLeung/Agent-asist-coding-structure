# 编码风格规范

## 命名规范

- 变量/函数：`lowerCamelCase`（语言社区常见约定优先）
- 类型/类：`UpperCamelCase`
- 常量：`UPPER_SNAKE_CASE`
- 文件名：以项目既有风格为准；新文件优先使用 `kebab-case`（文档）与 `snake_case`（脚本/配置）

## 结构与可读性

- 单一职责：模块/函数只做一件事
- 明确边界：输入校验、错误处理、资源释放必须可读
- 避免魔法值：抽出常量或枚举
- 明确依赖：入口处集中 import，减少隐式依赖

## 注释与文档

- 代码注释只解释“为什么”，不重复“做什么”
- 对外 API 必须有用法示例或最小调用方式说明
- 重要流程用文档描述，并链接到实现位置

## 错误处理

- 失败要可诊断：错误信息包含上下文但不包含敏感信息
- 兼顾用户与开发者：对外返回友好，对内日志完整

## 格式化与提交

- 避免无关格式化导致的噪音 Diff
- 变更应分层提交：先重构再改行为，或先改行为再清理
